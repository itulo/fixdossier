Sample security records

This is an unedited SECURITY-RECORD.md and security-record.json that fixdossier produced for a public repository. It lists the published security advisories and security-looking commits it found, the release that shipped each fix, and how that link was made. It shows what the output looks like on a real project, including the parts that need a human check.

Not requested or endorsed by the project. The project below did not ask for, review or endorse this record, and it is not claimed to use fixdossier. The record is generated from public GitHub data (published repository security advisories, releases, tags, merged pull requests and commit messages) using read-only API calls. If you maintain this project and want the record removed or corrected, write to contact@fixdossier.dev.

How it was generated

  • fixdossier v0.1.2 (commit f5d6fc5), run locally with node src/index.js --repo=owner/name --max_pages=10 on 2026-10-31. max_pages=10 is also the Action’s default.
  • Only published repository advisories are read. Draft or private advisories, and global advisories for a project’s dependencies, are not included.
  • The record is a snapshot of the day it was generated. Newer advisories and releases are not in it.

Run it on your repo

Save as .github/workflows/security-record.yml. Artifact mode is the default and needs only read permissions.

yaml
name: security-record
on:
  release:
    types: [published]
  schedule:
    - cron: '0 6 * * 1'   # weekly
  workflow_dispatch:
permissions:
  contents: read
  pull-requests: read
jobs:
  record:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4
      - uses: itulo/fixdossier@v0

The Action is free and MIT-licensed. See Build a dated record of security fixes for inputs and commit mode.
