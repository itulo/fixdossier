Free · MIT · GitHub Action

Your repo already knows when you shipped every security fix. Write it down.

fixledger is a free GitHub Action. It reads releases, tags, published GitHub security advisories, merged Dependabot/Renovate PRs, and security-looking commits — then writes a dated fix record and a support-period policy.

Get it on GitHub Release v0.1.0 Join the interest list

Use with uses: itulo/fixledger@v0 · https://itulo.github.io/fixledger/

What it does

Three files from the history you already have

Runs on every release and weekly with the default GITHUB_TOKEN. Commits the files or uploads them as a build artifact. If a permission is missing, it notes the gap instead of failing.

SECURITY-RECORD.md

Dated fix log

Each security fix mapped to the release that shipped it, with how the mapping was made, plus bot dependency updates.

security-record.json

Machine-readable

Same data as JSON (schema: fixledger/v1) for tooling and audits.

SUPPORT.md

Support policy

Built from your inputs: support period in months, optional EOL date, security contact — with a “supported until” date per release.

Sources it reads

  • Releases and tags
  • Published GitHub security advisories (GHSA) for the repo
  • Merged Dependabot and Renovate PRs
  • Commits whose messages look like security fixes (CVE…, GHSA…, “security”, XSS/SSRF/RCE…)

Install

Drop into a workflow

Copy from examples/workflow.yml. Artifact mode needs only contents: read; commit mode needs contents: write.

yaml 
permissions:
  contents: write        # commit mode; artifact mode: contents: read
  pull-requests: read
steps:
  - uses: actions/checkout@v4
  - uses: itulo/fixledger@v0
    with:
      support_period_months: 24
      eol_date: '2030-12-31'
      contact: security@example.com
      mode: commit                    # artifact (default) | commit | none

Why (context, not a promise)

Ordinary engineering hygiene that is useful under new EU rules

  • The EU Product Liability Directive (EU) 2024/2853 treats software as a product for products placed on the market from 9 Dec 2026. Courts can order disclosure of relevant evidence (Art. 9); some presumptions apply if it isn’t produced (Art. 10).
  • The Cyber Resilience Act (EU) 2024/2847 will expect manufacturers to state a support period and provide security updates (main obligations from Dec 2027).
  • A dated, versioned record of fixes and a published support policy is useful in either setting — it is not a certificate of compliance.
