Free · MIT · GitHub Action

Collect dated security-fix evidence from your GitHub history — then review it.

fixledger is a free GitHub Action for evidence collection and review support, not a complete security-fix inventory. It reads releases, tags, published GitHub security advisories, merged Dependabot/Renovate PRs, and security-looking commits — then writes a dated fix record and a support-period policy you can check before you rely on it.

Get it on GitHub Release v0.1.0 Join the interest list

Use with uses: itulo/fixledger@v0 · https://itulo.github.io/fixledger/

What it does

Three files that help you review what history shows

Runs on every release and weekly with the default GITHUB_TOKEN. Commits the files or uploads them as a build artifact. Output is starting evidence to review — silent fixes, keyword misses, and backport mapping errors still need a human pass. If a permission is missing, it notes the gap instead of failing.

SECURITY-RECORD.md

Dated fix log

Dated candidates mapped to a release when possible, with how each mapping was made, plus bot dependency updates — for review, not a guarantee of completeness.

security-record.json

Machine-readable

Same data as JSON (schema: fixledger/v1) for tooling and audits.

SUPPORT.md

Support policy

Built from your inputs: support period in months, optional EOL date, security contact — with a “supported until” date per release.

Sources it reads

  • Releases and tags
  • Published GitHub security advisories (GHSA) for the repo
  • Merged Dependabot and Renovate PRs
  • Commits whose messages look like security fixes (CVE…, GHSA…, “security”, XSS/SSRF/RCE…)
Coverage

What the record covers — and what it does not

  • Advisory-derived rows use the advisory’s patched_versions matched to a release tag (shown as “advisory patched_versions”).
  • Heuristic-derived rows use the first stable release on or after the fix date (shown as “date heuristic”) — can be wrong for backports and multi-branch repos.
  • Unmatched / unreleased fixes stay listed when no release mapping is found (sample stats include an “Unreleased fixes” count).
  • Sources skipped for permissions (401/403/404 or rate limit) are noted as gaps in the record instead of failing the run.
  • Numeric confidence scores are not in the Action yet (roadmap). Today each row’s mapping method is the transparency signal — as in the sample table’s “How mapped” column.

Install

Drop into a workflow

Copy from examples/workflow.yml. Artifact mode needs only contents: read; commit mode needs contents: write.

yaml 
permissions:
  contents: write        # commit mode; artifact mode: contents: read
  pull-requests: read
steps:
  - uses: actions/checkout@v4
  - uses: itulo/fixledger@v0
    with:
      support_period_months: 24
      eol_date: '2030-12-31'
      contact: security@example.com
      mode: commit                    # artifact (default) | commit | none

Why (context, not a promise)

Ordinary engineering hygiene that is useful under new EU rules

  • The EU Product Liability Directive Directive (EU) 2024/2853 treats software as a product for products placed on the market from 9 Dec 2026. Courts can order disclosure of relevant evidence (Art. 9); some presumptions apply if it isn’t produced (Art. 10). Official text: EUR-Lex ELI.
  • The Cyber Resilience Act Regulation (EU) 2024/2847 will expect manufacturers to state a support period and provide security updates (main obligations from Dec 2027). Official text: EUR-Lex ELI.
  • A dated, versioned evidence record and a published support policy can help in either setting — they are not a complete inventory or a certificate of compliance.
